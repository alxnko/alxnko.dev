No P0 blocker was established in the inspected paths. The rendered collar is a
polish issue, not a WCAG violation. The cached motion preference has initial-load
support; it is specifically a live-setting-change gap.

Independent code review also reproduced a related touch failure: a second finger
could clear a consumed press, and a later pointer-up could execute a delayed tap.
A short `pointercancel` was treated as a tap as well.
The correction belongs in `src/scene/input.ts`: keep a gesture-wide no-tap latch
through every remaining finger of a pinch/cancelled or consumed gesture. Release
still stops the motor; normal single-finger taps, drags, and pinch zoom remain.
The six focused gesture tests failed in four cases against the original input
implementation and all passed with the correction. Real mouse scene regression
and emulated mobile rain/interrupt cases also pass. The new multitouch sequence
uses synthetic PointerEvents at the real input boundary, not a physical phone.

The full Blender build/bake/export/optimize/poster/finalize/import-check pipeline
passed. Matching crops from the generated daylight posters provide
[before](../../audit-assets/2026-10-12/monitor-before.png) and
[after](../../audit-assets/2026-10-12/monitor-after.png) evidence of collar removal.
The final GLB is 241.1KiB with 26,216 triangles; build budgets pass, including
29.5KiB initial JS and 166.9KiB lazy scene JS (gzip). Type checking has no errors
or warnings, and all 390 unit tests pass. Asset contract checks were rerun after
the bake: 13 checks pass.

The full desktop/mobile browser run initially returned 167 passes, 20 conditional
skips, and one failure in an existing keyboard-focus test. Trace inspection showed
the camera correctly handed focus to GitHub between two separate test reads; the
test then sent an extra Tab and reached Telegram. The assertion now reads the
active contact and panel ID together, so it waits for the existing hand-off
without racing it. No product focus behavior was changed and no retries were added.
The complete confirmation run passed: **168 browser tests, 20 conditional skips,
zero failures**, across desktop and mobile projects (4.5 minutes).

## Production deployment

The first deployment below blocked physical desk input during foreground commands.
The owner then clarified that this interpretation was wrong: table buttons should
continue to work while `cmatrix` plays. The current design contract supersedes the
initial busy-control policy. Busy paddle clicks move the desk directly without
running another shell command; holds stay available. Gesture cancellation and
pinch suppression are retained. Correction verification and deployment are
recorded separately below.

After owner approval, deployed the verified build to Cloudflare Pages production
on 2026-10-12 at approximately 17:45 Asia/Bishkek:
[deployment c67949f7](https://c67949f7.alxnko-dev.pages.dev).
Previous production deployment `51a41584-56cf-4f7d-8404-9c7f51b7169d`
remains available for rollback. This was a direct upload from the reviewed local
working tree; source changes remain uncommitted.

Production browser verification on `https://alxnko.dev/?3d` loaded the new scene,
and SHA-256 hashes of the served manifest and GLB matched the local build.
Home and scene assets returned HTTP 200 with the expected types; enforced CSP
and `nosniff` remain present. The live terminal ran `cmatrix --both`, displayed
rain while busy, and Ctrl+C restored the prompt and hid the rain. Existing
Cloudflare-injected scripts remain blocked as recorded above.

### Corrected physical-control policy

Removed the scene's terminal-busy paddle gates and hold cancellation. Idle clicks
still execute and echo `desk`; busy clicks use `AppWorld.setDesk` directly with
the existing presets and clamped 5cm increments, leaving the shell's foreground
command and queued input untouched. Holds remain usable, and `input.ts` keeps
its gesture-wide pinch/cancellation safeguards.

Independent review found no actionable issue. All 390 unit tests passed; lint
reported zero errors/warnings and one existing hint. The focused real-mouse
browser regression passed (58.8s), testing both matrix modes, every preset,
up/down clicks and holds, changing rain and busy state after movement, q/Ctrl+C
exit, and idle controls. Budgets pass: 29.6KiB initial JS and 166.8KiB lazy scene
JS gzip. Generated geometry was unchanged; a fresh production build passed.
Deployed the correction to production as
[ccd53fc5](https://ccd53fc5.alxnko-dev.pages.dev) on 2026-10-12.
On the live custom domain, a real click on preset 3 moved the desk from 74cm to
112cm while `cmatrix --both` stayed busy with rain visible; Ctrl+C then stopped
the rain. The production scene/script asset names match the local build.

## Verification priorities for the next refinement

These are coverage tasks rather than newly established failures:

- Recheck projected contact hit areas at the monitor view, not only logical CSS
  dimensions. Existing scene tests already cover touch targets and focus flights.
- Test text/browser zoom and portrait/landscape alongside day/night and lite/3D.
- Test rapid flight/theme reversal, touch cancellation, loss of focus during a
  hold, and hidden-tab return. Keep physical desk timing separate from DOM timing.
- Measure LCP/INP/CLS and frame behavior on representative hardware before
  proposing rendering or dependency changes.

Suggested sequence: `/impeccable animate` for the live motion preference and
interruption pass; `/impeccable adapt` for zoom/touch verification;
`/impeccable optimize` only against measured bottlenecks; `/impeccable polish`
after the concrete defects are resolved. The host analytics mismatch requires
deployment configuration work rather than a visual polish command.
